    7. Implementación de Ajax en una aplicación Spring MVC

    7.1. El papel de AJAX en una aplicación web

    Por el momento, los ejemplos de aprendizaje estudiados tenían la siguiente arquitectura:

    Para pasar de una vista [Vue1] a una vista [Vue2], el navegador:

    • envía una solicitud a la aplicación web;
    • recibe la vista [Vue2] y la muestra en lugar de la vista [Vue1].

    Este es el esquema clásico:

    • solicitud del navegador;
    • el servidor web genera una vista en respuesta al cliente;
    • el navegador muestra esta nueva vista.

    Desde hace algunos años existe otra forma de interacción entre el navegador y el servidor web: AJAX (Asynchronous JavaScript and XML). De hecho, se trata de interacciones entre la vista que muestra el navegador y el servidor web. El navegador sigue haciendo lo que sabe hacer, es decir, mostrar una vista HTML, pero ahora es controlado por JavaScript integrado en la vista HTML que se muestra. El esquema es el siguiente:

    • en [1], ocurre un evento en la página que se muestra en el navegador (clic en un botón, cambio de texto, etc.). Este evento es interceptado por JavaScript (jS) integrado en la página;
    • en [2], el código de JavaScript realiza una solicitud HTTP tal como lo habría hecho el navegador. La solicitud es asíncrona: el usuario puede seguir interactuando con la página sin que se bloquee mientras espera la respuesta a la solicitud HTTP. La solicitud sigue el proceso clásico de procesamiento. Nada (o casi nada) la distingue de una solicitud convencional;
    • en [3], se envía una respuesta al cliente jS. En lugar de una vista HTML completa, se envía más bien una vista HTML parcial, un flujo XML o jSON (notación de objetos JavaScript) lo que se envía;
    • en [4], el JavaScript recupera esta respuesta y la utiliza para actualizar una sección de la página HTML que se muestra.

    Para el usuario, se produce un cambio en la vista porque lo que ve ha cambiado. Sin embargo, no hay una recarga total de la página, sino simplemente una modificación parcial de la página que se muestra. Esto contribuye a dar fluidez e interactividad a la página: como no hay una recarga total de la página, podemos gestionar eventos que antes no se podían manejar. Por ejemplo, ofrecerle al usuario una lista de opciones a medida que va ingresando caracteres en un campo de entrada. Con cada nuevo carácter que se escribe, se envía una solicitud AJAX al servidor, el cual devuelve otras sugerencias. Sin Ajax, este tipo de ayuda para la entrada de datos era imposible anteriormente. No se podía recargar una nueva página con cada carácter escrito.

    7.4. Aplicación web de una sola página

    7.4.1. Introducción

    La tecnología Ajax permite crear aplicaciones de una sola página:

    • la primera página se obtiene mediante una solicitud convencional del navegador;
    • las páginas siguientes se obtienen mediante llamadas Ajax. Por lo tanto, al final, el navegador nunca cambia de URL y nunca carga una nueva página. A este tipo de aplicación se le denomina «aplicación de página única» (APU) o, en inglés, «Single Page Application» (SPA).

    • en [4], un enlace nos permite regresar a la página 1 mediante una llamada Ajax;
    • en [5], el URL no ha cambiado. La página que se muestra es la página 1.
